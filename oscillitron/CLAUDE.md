# Oscillitron — Go runtime

This subproject is the **code** for Oscillitron. The design lives in the parent project:

- Parent `CLAUDE.md`: `../CLAUDE.md` — project-wide conventions (provenance rule, folder layout) and the locked architectural decisions.
- Parent `INDEX.md`: `../INDEX.md` — entry point for design docs.
- Library plan v0.2: `../scratch/library-plan.md` — the spec this code implements. Read §5 for type signatures and §9 for the first-week task order.
- Working design notes: `../scratch/design-notes.md` — open architectural questions still in flight (AP shape, inhibitor placement, summary format).

The parent project is the source of truth for **what** to build and **why**; this subproject is the source of truth for **how it's currently built**.

What's here:

- **Session envelope** (`pkg/session`) — uniform-node + evaluate/execute shape. Fields: `SchemaVersion`, `ID`, `ParentID`, `RootID`, `Path` (root→this), `ScopeHandle`, `Input` (`Payload{Kind, Content, ContentHash}`), `OutputSchema`, `Classification`, `NeedsVerification`, `VerifySpec`, `Budget`, `Evaluate{Playbook, Rationale, Confidence, TokensUsed}`, `Execute{Category, EmitSubtree|ReturnResult|VerifierSignal, TokensUsed}`, `ExitReason`, `Trace`, `Audit`. No `BrainFunction` field — playbook is *picked by evaluate*, not declared. `NewRoot()` and `NewChild()` helpers stamp the call-tree plumbing. Three execute categories: `emit_subtree` (plan), `return_result` (process, compose), `verifier_signal` (critique, verify_grounded). Predicates: `IsComplete`, `IsLeaf`, `IsInhibited`, `Depth`.
- **Classification levels** (`pkg/classification`).
- **Notice layer** (`pkg/notice`, v3.1 prompt-side + v3.2 response-side + v3.3 stamping helper) — cheap deterministic detectors for inadequacy signals. **v3.1 prompt-side** (notice.go): `InputOverflowsContext` (input tokens ≥ model context window — Error severity), `InputApproachingContext` (input ≥ 80% of window — Warning), `PersonaHeavy` (system prompt ≥ 3× user content — Warning; ≥ 10× = Error, the Hermes-overload regime). `Inspect(CallInspection)` returns an `Assessment{Detections, Score}`. **v3.2 response-side** (response.go): `RefusalLanguage` (model declines — Warning), `SelfCorrection` (mid-stream reversal — Info; ≥2 occurrences → Warning), `InternalInconsistency` (hedging language co-occurring with high-confidence claims — Warning). `InspectResponse(ResponseInspection)` runs the response-side detectors. **Confidence handling** (v3.2): `ExtractConfidence(raw)` parses the `confidence: 0.X` annotation from raw response text (case-insensitive, last match wins, clamped 0-1). `EffectiveConfidence(raw, assessment)` applies multiplicative downgrades — Refusal × 0.3 (strongest), InternalInconsistency × 0.6, SelfCorrection × 0.8/0.95 by severity, generic Warning × 0.85, generic Error × 0.5. `Inspector` is the integration shim adapters consume via `Config.Inspector`; gains `InspectResponse(string)` method in v3.2 alongside the v3.1 `Inspect(systemPrompt, userContent)`. `DefaultApproxTokens` (bytes/4) is the default tokenizer; override for accuracy. Tunables `ApproachingThreshold`, `PersonaHeavyRatio`, `PersonaCriticalRatio` exposed as package vars. Wired in `pkg/adapter/ollama`: emits `ollama.notice_assessment` (pre-call signals) and `ollama.notice_response_assessment` (response signals + raw/effective confidence). **v3.3 `EffectiveConfidenceFromRaw(raw, *Inspector)`** is the adapter-agnostic one-call helper that extracts confidence from raw text and applies signal adjustments in a single call — used by ollama's `applyEffectiveConfidence` to stamp the recovered value onto `Execute.ReturnResult.Confidence` when the minimal-output path produces an unstructured-fallback Execute (JSON-parsed confidences are left alone). Notice is **observability**, not enforcement — does not alter calls. The act-layer rule table that consumes these signals lands in v3.4.
- **Stakes levels** (`pkg/stakes`) — the v3.0 effort-routing axis, distinct from `pkg/classification` (confidentiality routing). `Level` is `low` | `medium` | `high`; zero value reads as `medium` via `Effective()` so pre-v3.0 callers retain their behavior. `AttemptScale(level, baseN)` returns the effective attempt count: Low→1 (cheap path, voting overkill), Medium→base, High→2×base. The v3.0 consumer is `pkg/benchmark/orchestrator.Vote`; the bench's per-case stakes are assigned via `cmd/bench --stakes` (low|medium|high|rotate). Future v3 phases extend stakes-driven decisions to coping (signal-driven re-runs, frontier escalation, critique injection) per `scratch/v3-design.md` §4.4.
- **Thinking policy** (`pkg/thinking`) — per-call reasoning-mode selector for substrates that expose a thinking trace (qwen3.x, deepseek-r1, magistral, gpt-oss, exaone-deep, glm-5, kimi-k2-thinking, gemma4). `Policy` interface: `ShouldThink(env session.Envelope) bool`. Same shape as stakes — variable substrate effort the orchestrator turns per-call. Adapters translate the decision into the substrate-specific request field (e.g., `"think": false` on Ollama's `/v1/chat/completions`). Substrates without reasoning mode silently no-op the flag (architectural lock 2026-05-24). Implementations inspect Stakes, Playbook, Path to decide.
- **Adapter** (`pkg/adapter`) — interface has two methods: `Evaluate(ctx, env) (env, err)` (picks the playbook) and `Execute(ctx, env) (env, err)` (runs the chosen playbook). Per-invocation session lifecycle is the adapter's responsibility. `RawCaller` is an optional interface an Adapter may implement for freeform prompts that bypass playbook instructions and response_format — natural text in, natural text out. Used by `DeriveGoal` and `LLMExtractor` for goal/answer extraction.
- **Stub adapter** (`pkg/adapter/stub`) — configurable per-playbook. `WithDefaultPlaybook` / `WithEvaluator` shape Evaluate; `WithEmitSubtree` / `WithReturnResult` / `WithVerifierSignal` shape Execute by playbook. Counters: `Calls`, `EvalCalls`, `ExecuteCalls`, `CallsForPlaybook`. Used by tests.
- **Hermes adapter** (`pkg/adapter/hermes`) — adapter against the OpenAI-compatible HTTP gateway shipped by hermes-agent. Two-step contract: `Evaluate` POSTs to a dedicated `EvaluateEndpoint` (cheap-local-first per lock) and parses `{playbook, rationale, confidence}` from the run's structured output; `Execute` looks up `ExecuteEndpoints[playbook]` and parses one of three playbook-specific JSON payloads (emit_subtree for plan, return_result for process/compose, verifier_signal for critique/verify_grounded). Session IDs are **per-AP per-phase** (`<envID>:<phase>`), giving each invocation a fresh Hermes session per the locked "Specialist vs. invocation" rule (clean isolation, no cross-invocation contamination at the working-memory level). KV-cache hits across calls come from the underlying engine's global prefix caching (vLLM-style — keyed by token-prefix bytes, not by session_id), not from sharing sessions across APs. The `cmd/probe-prefix-cache` probe verifies that the deployed engine does this. Per-AP isolation is also a prerequisite for sibling concurrency (`runner.Config.MaxConcurrency`): concurrent calls on the same session_id would serialize at the engine layer or behave unpredictably. Approvals are rejected as inhibited (orchestrator owns gating, not the substrate). Two builders: `SingleEndpoint(baseURL, model)` binds evaluate + every v0 playbook to one Hermes (v0 dev shape); `MultiEndpoint(evaluate, byPlaybook)` routes each playbook to its own Hermes process (per-instance playbook substrate, locked 2026-05-18) and rejects missing entries up front. An httptest-based smoke test (`TestMultiInstance_RoutesEachPlaybookToOwnHermes`) stands up N independent fake Hermeses and confirms each `/v1/runs` request lands on the right server — the canary against routing regressions silently mixing per-playbook state. `RequireStructured` toggles strict JSON enforcement; default false (low-confidence fallback per category). Per-step `RawEvaluateInstructions` / `RawExecuteInstructions` override the default prompts. Cost ledger records once per phase. SSE decoder in `sse.go` is unchanged from the old shape.
- **Inhibitor** (`pkg/inhibitor`) — edge-property interface unchanged. Implementations updated to read the new envelope:
  - `pkg/inhibitor/hardcap` — path-depth cap (unchanged; reads `Edge.Path` length).
  - `pkg/inhibitor/confidence` — reads `Execute.ReturnResult.Confidence`. APs that didn't emit a return_result are skipped (missing signal, not a negative signal).
  - `pkg/inhibitor/repetition` — reads `Execute.ReturnResult.Result.Content`.
  - `pkg/inhibitor/contradictions` — reads `Execute.ReturnResult.Signals.Contradictions`.
  - `pkg/inhibitor/composite` — combines members; Abort > Restart > Continue precedence (unchanged).
- **Runner** (`pkg/runner`) — recursive tree-walker on the envelope. `Run(ctx, cfg, root) (Result, error)`. Calls `adapter.Evaluate` then `adapter.Execute` on every AP; branches on `Execute.Category`: `return_result` bubbles, `verifier_signal` records in `RunState`, `emit_subtree` constructs child envelopes and dispatches in **randomized sibling order** (`math/rand/v2` PCG; seedable via `Config.Rand`). **The runner owns no VRAM logic.** `Config.Governor` (a `*vram.Governor`, optional) handles all per-byte accounting through Acquire/Release; the runner just consults it. `Config.MaxConcurrency` bounds sibling goroutines per dispatch wave: `0 = library-managed (auto-builds governor with DefaultVRAMModel + MaxConcurrencyCeiling=8; probe failure falls back to serial)`, 1 = strict serial (no auto-governor — operator's deliberate opt-out), N>1 = static cap (further tightened by `governor.Ceiling` when wired). Library-managed mode emits a `runner.auto_governor_wired` trace event at Run start; probe-failure fallback emits `runner.probe_failed_serial_fallback`. Each AP's Evaluate+Execute window is bracketed by a single Acquire/Release pair on the governor (released explicitly before descend so children claim their own slots — holding through descend would deadlock at depth ≥ ceiling). **Strict cancellation under concurrency**: the first sibling to fire inhibitor.Abort cancels the others via context. Inhibitor fires on every parent→child edge after the child resolves (root not checked). Restart→Abort downgrade still in effect. `Config.MaxInputBytes` optionally inhibits any AP whose `env.Input.Content` exceeds the budget. Belt-and-suspenders `MaxDepth` cap alongside per-AP `Budget.DepthRemaining`. `Result` carries `Root`, `ResolvedPayload`, `Subtree`, `State`. Recomposer is required for any tree with emit_subtree APs. Race-detector-clean.
- **Recomposer** (`pkg/recomposer`) — `Recompose(ctx, RecomposeSpec, []ReturnResultPayload) (ReturnResultPayload, error)`. Two implementations: `Concat` joins `Result.Content` with a caller-supplied `Separator` (`DefaultSeparator = " | "` suggested) and is the text-level v0 default; `Synth` plugs an LLM-shaped `Synthesizer` interface into the same fold machinery so reductions go through a real model rather than string-joining. Both honor the same spec semantics: `RecomposeNone` returns the zero payload, `RecomposeSequential` folds left-to-right, `RecomposePairwise` folds pairwise across rounds (odd-count rounds pass the trailing element through) — N-1 reductions in both shapes. Both take weakest-link confidence (`min`) and union signal bundles (Contradictions/OpenQuestions concat, GroundedPass AND when both set, nil otherwise). `Synth` invokes its synthesizer once per binary reduction with `{Left, Right, RecomposeSpec, StepIndex}`; the response may override confidence (zero falls back to weakest-link). Two Synthesizer implementations: `SynthStub` (tests/demo, configurable format) and `AnthropicSynthesizer` (frontier-backed; default model `claude-sonnet-4-6`, parses `{content, confidence}` from the Messages API). Compose-as-a-dispatched-AP with actual scope channels is a v1 concern; v0 owns the orchestration in the runner+recomposer pair.
- **Demo** (`cmd/oscillitron`) — exercises the uniform-node + evaluate/execute call tree end-to-end. Without `--hermes` or `hermes.url` in config, it uses the stub adapter (root plan emits three process APs + one critique, all three Execute categories demonstrated, Concat recomposer with `DefaultSeparator`). With `--hermes <URL>` (or `hermes.url=<URL>` in `--config`), it swaps in `hermes.SingleEndpoint`. If `--config` provides any `hermes.endpoints.<playbook>.url`, multi-endpoint mode wins. CLI flags: `--task`, `--seed`, `--max-depth`, `--depth-budget`, `--config`, `--hermes`, `--hermes-model`, `--strict`, `-v`. Concurrency: `--max-concurrency` (0 = no per-wave goroutine cap, 1 = strict serial, N>1 = cap at N). VRAM governor (library-managed by default — omit the architecture flags and the demo builds a `vram.AutoGovernor` from `DefaultVRAMModel` under `MaxConcurrencyCeiling=8`; supply all four for accurate per-model throttling): `--model-layers`, `--model-kv-hidden`, `--model-kv-dtype-bytes`, `--model-context-size`, plus optional `--model-name`, `--prefix-tokens`, `--governor-ceiling` (default `runtime.NumCPU()`), `--governor-reserve-fraction` (default 0.05), `--vram-budget` (pins what the probe reports), `--max-input-bytes`.
- **Properties config** (`pkg/config`) — tiny stdlib-only `.properties` loader (Java-style `key=value`, `#` / `!` comments, dotted keys for hierarchy, typed accessors). Used by the demo for both single-endpoint (`hermes.url`) and multi-endpoint (`hermes.endpoints.<bf>.url`) Hermes setups. Deliberately a fraction of Spring Boot's surface — no profiles, no relaxed binding, no SpEL.
- **Cost tracker** (`pkg/cost`) — `Pricing` + `Tracker` with actual + frontier-counterfactual ledgers. Wired through both the Hermes adapter (per-phase `Record` calls populate `env.Trace.CostUSD` and `env.Trace.CostVsFrontierBaselineUSD` inline so the lean envelope carries cost) and the runner (`Config.Cost` is an optional observer; `Result.State.CostSummary` is snapshotted at end of Run, including on the error path).
- **VRAM probe + estimator** (`pkg/vram`) — platform probes and a per-call KV-cache estimator. `Probe` interface; auto-detecting `AutoChain` tries probes in priority order: operator override → nvidia-smi → rocm-smi → darwin-unified (build tag) → Linux DRM sysfs (build tag) → /proc/meminfo. `SlidingWindowEstimator` caps per-session bytes at `min(prefix + observed, ContextSize) × BytesPerToken + ModelResidentBytes`; `PrefixCacheGlobal` subtracts the prefix when the engine deduplicates it across sessions. **No magic-number defaults**: `EstimatorForModel(numLayers, kvHiddenDim, kvDtypeBytes)` computes `BytesPerToken` from real transformer architecture (returns zero on bad input, surfacing misconfiguration at config time). `DefaultSlidingWindowEstimator` and the `80,000`-byte fallback are deleted. `DefaultVRAMModel` (Llama-7B-class conservative architecture + 3 GB resident) and `AutoGovernor(tracer)` are the building blocks of the runner's library-managed concurrency path (`MaxConcurrency=0`); `ModelSpec.ModelResidentBytes` feeds the estimator's per-session overhead so N×3GB OOM scenarios on unified-memory hosts get caught before launch. Honest about platform gaps (Windows + non-NVIDIA has no auto-detect path); see `references/vram-platform-coverage.md`.
- **VRAM governor** (`pkg/vram.Governor`) — the process-wide VRAM manager. Every component running inference against a shared substrate (runner, grader, future bench drivers) acquires leases from the same Governor. The governor owns probe selection (auto-detects via `vram.Auto()`; `ProbeOverride` for tests), per-call byte estimation (built internally from the operator's `ModelSpec`), accounting, and FIFO budget enforcement. The runner is **not** entangled — it has no VRAM fields; it just consults `Config.Governor` if wired. `GovernorConfig` requires `Model` (a `ModelSpec` with `Layers`, `KVHiddenDim`, `KVDtypeBytes`, `ContextSize`, `PrefixTokens`); optional `Ceiling` (default `runtime.NumCPU()` — derived from hardware, not a magic constant), `ReserveFraction` (default 0.05 = 5% of available, a fraction not an absolute), `Tracer`, `ProbeOverride`. `NewGovernor` returns an error on invalid `ModelSpec` or `ReserveFraction ≥ 1` — refuses to start with garbage architecture rather than silently producing fabricated byte counts. `Acquire(ctx) → *Lease` blocks until the lease fits under both the ceiling and `Probe.AvailableBytes × (1 − ReserveFraction)`; cancellation aborts the wait. Probe failure degrades to ceiling-only enforcement (probe outage doesn't stop the runtime). FIFO wake order — starvation-free in v0 because all callers share one model/estimator (per-call cost is identical across waiters). Cancel-after-wake re-wakes the next waiter so a freed slot can't be stranded. Nil `*Governor` is safe to call (Acquire returns a no-op lease) so consumers can opt in without nil checks. **CPU/system-memory**: substrate-agnostic; Linux CPU-only falls through to `/proc/meminfo`, Apple Silicon uses `darwin-unified` (covers both CPU and GPU via unified memory), Intel Mac / Windows CPU-only require `SetOverride` or a custom probe.
- **Eval harness** (`pkg/eval`) — decoupled from the orchestrator (Runner is `func(ctx, Task) (string, error)`); no changes needed for the call-tree refactor.
- **Curation driver** (`pkg/curation`) — cold-path side of the three-tier architecture. `curation.Run(ctx, cfg)` reads a bench's `--stream-out` JSONL, filters cases passing `MinScore`, batches the candidates, dispatches each batch to `Config.Adapter` (a "cold-path session" — typically Hermes with a stable `SessionIDPrefix` for memory continuity across batches), parses the model's `SelectionResponse` JSON listing chosen `case_id`s, and writes the selected (prompt, output) pairs to `Config.Store`. `DefaultPromptTemplate` builds the persona-framed "you are the {action} specialist" cold-path prompt; operators override with `PromptTemplate` for custom selection criteria. `OrchestratorAllowlist` restricts which orchestrators contribute candidates (typically skip vote-style multi-call orchestrators whose `Raw` is a concatenation). Best-effort: per-batch adapter / parse failures increment `Result.BatchesFailed` but don't fail the run. Tolerates markdown-fenced JSON via the same brace-balancing scanner pkg/grader / pkg/judge use. Skips hallucinated `case_id`s the model returns that weren't actually in the batch. Never touches warm-path state — cold path and warm path communicate ONLY through the per-action `exemplar.Store`.
- **Curated adapter** (`pkg/adapter/curated`) — warm-path bridge in the three-tier curation architecture. `curated.WithStore(inner, store)` returns an `adapter.Adapter` that on every `Execute` retrieves top-K relevant exemplars for `env.Evaluate.Playbook` from a `pkg/exemplar.Store` and prepends them as a `[similar-examples]` block to `env.Input.Content` before calling the inner adapter. `Evaluate` passes through unchanged — augmenting playbook *selection* with exemplars is meta-level different from augmenting playbook *execution* and is intentionally deferred. Pass-through (no augmentation) on: nil store, missing playbook, empty corpus, retrieval error (best-effort substrate), or all exemplars excluded by `MaxExemplarTokens`. Inner errors propagate verbatim. `TopK` (default 3), `MaxExemplarTokens` (0 = uncapped), `ActionOverride` (override `env.Evaluate.Playbook` as the retrieval key — needed when the warm-path orchestrators' playbook differs from the action the cold path wrote under), and `Formatter` (default builds a byte-stable `[similar-examples count=N]…` block so identical exemplar sets across consecutive calls produce identical prefix bytes — KV-cache prefix hits compound) are all tunable. Per-call observability via optional `Tracer`: `curated.exemplars_retrieved`, `curated.passthrough` (with reason), `curated.retrieval_failed`. Works for every substrate (Hermes, Anthropic, stub, future) without modifying any of them.
- **Exemplar substrate** (`pkg/exemplar`) — per-action store for curated AP outcomes. `Exemplar{Action, Prompt, Output, Score, SourceCase, Tokens, AddedAt, LastRetrievedAt}` is one preserved (prompt, output) pair worth retrieving as a few-shot example. `Store` interface (Add/Retrieve/GC); `FileStore` JSON-backed (one file per action under `Dir`), atomic write via tmp-and-rename, mutex-serialized for concurrent safety. `Add` dedupes by `(Action, SourceCase)`. **`Retrieve` ranks by BM25 over Prompts** (k1=1.5, b=0.75, IDF with +1 smoothing) with curation Score then AddedAt as tiebreakers; when BM25 scores tie at zero (query shares no tokens with corpus) the tiebreakers carry. Indexes Prompts only — past Outputs aren't query-side signal. Tokenizer is lowercase + Unicode letter/digit split + single-char drop (preserves `e1`, `10`, `eV`-style technical tokens; skips stop-letter noise). `GC` enforces `MaxTokensPerAction` budget by evicting least-recently-retrieved exemplars. `ApproxTokensByChars` is the default token estimator (len/4 + 1). This is the substrate layer of the three-tier curation architecture (warm path / cold path / substrate); the cold-path driver and the wrapping adapter that retrieves at warm-path time land in subsequent v2 PRs.
- **Trace** (`pkg/trace`) — slog-backed `Tracer` with `Info` / `Error` sugar helpers and a `Discard` no-op. Oscillator, runner, and the demo now emit through `trace.Tracer` rather than `*slog.Logger` directly. The fat learning-loop trace record (verifier feedback, retrieval refs, etc.) lives here per the lean-AP-vs-fat-trace split. **Correlation IDs via ctx**: `trace.WithCorrelation(ctx, key, value)` stamps a key=value into the context; `CorrelationFrom(ctx)` reads them. The `Slog` backend prepends correlation pairs to every event's attrs automatically, so events emitted by descendants (runner/governor/adapter from within an orchestrator call) carry the originating bench case + orchestrator + attempt without those layers needing to know. Same-key overwrites in place; order preserved. **Multi backend**: `trace.Multi{a, b, ...}` fans every event to N tracers — operators get local stderr (Slog) AND remote shipping (OTel) without picking one. Nil entries skipped. **OTel adapter** (`pkg/trace/otel`): `otel.New(ctx, serviceName)` returns a Provider whose `Logger` is a slog.Logger backed by the `otelslog` bridge → OTel LoggerProvider → OTLP HTTP exporter. Wrap in `trace.Slog{}` to use as a Tracer. Operators configure the exporter via `OTEL_EXPORTER_OTLP_*` env vars; Datadog/Splunk operators run an OTel collector that ingests OTLP and routes. `pkg/trace` stays stdlib-only — the OTel dependency lives only in this subpackage so importing `pkg/trace` doesn't pull OTel transitive deps.
- **Verifier policy** (`pkg/verifier`) — implements the locked-2026-05-20 phase ramp. `Policy.ShouldCritique(action, parentOverride, rand)` returns whether to emit a critique on a return_result. Bootstrap (`invocations < BootstrapThreshold`) → 1.0; steady-state → `max(floor, 1 - happiness_wilson_lower_bound)` over a sliding ring window of judge-sampling agreements. `HappinessScope ∈ {global, per_action}` is runtime-configurable; telemetry is populated for both regardless of which drives the rate. Wilson lower bound uses Acklam's inverse normal CDF approximation (no external math libs). Parent override (envelope.NeedsVerification) forces critique on top of the baseline; suppression by parent is not allowed. v0 defaults via `DefaultConfig()` mirror the lock (10k bootstrap, 15% floor, 2k window, 95% CI, global scope). `RecordJudgeAgreement(action, agreed)` is the entry point the judge layer uses to feed happiness.
- **Judge sampling** (`pkg/judge`) — the audit tier that feeds the verifier policy's happiness signal (locked 2026-05-19; 100% un-grounded, 10% grounded). `Judge` interface produces a frontier verdict on a `Request{Target, LocalVerdict, LocalIssues}`. `Sampler.ShouldJudge(target, rand)` reads `target.Execute.ReturnResult.Signals.GroundedPass` to decide which tier applies (nil → un-grounded → 100%; non-nil → grounded → 10%). `DefaultSamplePolicy()` returns the locked rates. Two implementations ship: `Stub` (tests + demo, configurable verdicts) and `AnthropicJudge` (frontier-backed; calls the Anthropic Messages API with a structured-output prompt, parses `{verdict, issues}`, tolerates markdown-fenced JSON). Built on `pkg/anthropic`.
- **Anthropic API client** (`pkg/anthropic`) — stdlib-only client for the Anthropic Messages API. POST `/v1/messages` with `x-api-key` + `anthropic-version` headers. Single `Messages(ctx, req)` method; streaming and tool-use are out of scope for the audit / synthesis use cases. Shared by `pkg/judge.AnthropicJudge` and `pkg/recomposer.AnthropicSynthesizer`.
- **Semantic pool** (`pkg/semanticpool`) — shared-knowledge store per the parent CLAUDE.md "Per-instance vs. shared resources" lock. `Pool` interface (`All`, `Get`); `FilePool` is JSON-backed with mtime-based reload; `Static` is in-memory for tests. v0 read shape: whole pool injected as a stable preamble. `RenderPreamble` produces a byte-stable text block (`[semantic-pool: N entries]\n- id: content\n...\n[/semantic-pool]`) — deterministic order means KV-cache hits compound. Soft budget: 2000 tokens / 8 KB; over-budget snapshots emit a warning trace via the adapter. Programmatic writes deferred to the curation layer.
- **Anthropic adapter** (`pkg/adapter/anthropic`) — `adapter.Adapter` implementation backed by `pkg/anthropic`. One model per adapter instance (typically Haiku for the orchestrator path, Sonnet for the frontier baseline). Evaluate calls the Messages API with a playbook-pick prompt and parses `{playbook, rationale, confidence}`; Execute dispatches per playbook and returns the right Execute payload (emit_subtree for plan, return_result for process/compose, verifier_signal for critique/verify_grounded). Tolerates markdown-fenced JSON. Used by `cmd/phase1` to drive both sides of the kill-or-proceed measurement.
- **Ollama-direct adapter** (`pkg/adapter/ollama`) — direct-to-Ollama adapter that bypasses Hermes for small substrates. **v3.1**: optional `Config.Inspector *notice.Inspector` runs prompt-side detectors pre-call; emits `ollama.notice_assessment` trace events when signals fire. Observability-only — doesn't alter the call. Future v3 phases extend this hook with response-side signals + act-layer coping decisions. Hermes is an agentic substrate whose own docs (`~/hermes-agent/website/docs/guides/local-ollama-setup.md`) recommend ≥30B models for reliable tool-call behavior; small models (≤7B) like phi4-mini get crushed by the agentic envelope (~4k tokens of boilerplate per request) and degenerate into truncated gibberish. This adapter sends only the playbook instructions + AP input to Ollama's OpenAI-compatible `/v1/chat/completions` endpoint — no agentic envelope. Same two-step contract (`Evaluate` / `Execute`), same JSON payload protocol as the Hermes adapter — drop-in substrate swap. `SingleEndpoint(baseURL, model)` and `MultiEndpoint(evaluate, byPlaybook)` builders mirror the Hermes shape. Surfaces OpenAI-style `finish_reason` (`stop` / `length` / `content_filter` / `tool_calls`) in a per-call `ollama.call_completed` trace event — something Hermes's `/v1/runs` surface doesn't expose — so categorize can distinguish truncation from natural stop. Cost tracker + semantic pool integration parity with Hermes. `Config.SystemPreamble` is prepended to every call (Evaluate, Execute, RawCall) as a universal behavioral directive — injected before the semantic pool preamble. Implements `adapter.RawCaller` for freeform prompts that bypass playbook instructions. Instructions + parser code duplicated from `pkg/adapter/hermes`; consolidate into a shared package when a third substrate motivates it.
- **vLLM-direct adapter** (`pkg/adapter/vllm`) — direct-to-vLLM adapter that bypasses Hermes for production GPU clusters. vLLM (https://docs.vllm.ai) is a high-throughput inference server built for serving capable models on serious hardware — paged-attention KV management, continuous batching, tensor-parallel sharding across multiple GPUs. It is *not* an agentic substrate. Operators who run production vLLM clusters want a direct, non-agentic path: Hermes's tool-call envelope is wasted overhead when the orchestrator already owns planning, critique, and recomposition outside the substrate call. Distinct framing from `pkg/adapter/ollama` — this isn't about small models being crushed (vLLM serves Llama-3.3-70B / Qwen2.5-72B / Mixtral-class models just fine); it's about not paying for an agent envelope on top of a production cluster. Same two-step contract (`Evaluate` / `Execute`), same JSON payload protocol — drop-in substrate swap. `SingleEndpoint(baseURL, model)` and `MultiEndpoint(evaluate, byPlaybook)` builders mirror the Hermes / Ollama shape. Default base URL `http://127.0.0.1:8000` (vLLM's `vllm serve` listen default). Surfaces OpenAI-style `finish_reason` in a per-call `vllm.call_completed` trace event so categorize can distinguish truncation from natural stop. Cost tracker + semantic pool integration parity with Hermes / Ollama. **Explicit-only in bench**: `--orchestrator-substrate=vllm` is required; `auto` never picks vllm (the auto rule targets small substrates that Hermes crushes — wrong heuristic for a production cluster).
- **LM-Studio-direct adapter** (`pkg/adapter/lmstudio`) — direct-to-LM-Studio adapter that bypasses Hermes. LM Studio (https://lmstudio.ai) is the easiest local-LLM server for desktop operators — built-in HuggingFace browser, GUI for picking the loaded model, OpenAI-compatible `/v1` surface on `127.0.0.1:1234` by default. For Oscillitron users on a dev machine, LM Studio is often the loaded gun already pointed at their GPU. This adapter posts only the playbook instructions + AP input to `/v1/chat/completions` — no agentic envelope. Same two-step contract (`Evaluate` / `Execute`) and JSON payload protocol as the Hermes / Ollama adapters; drop-in substrate swap. `SingleEndpoint(baseURL, model)` and `MultiEndpoint(evaluate, byPlaybook)` mirror the other direct-substrate adapters. Surfaces OpenAI-style `finish_reason` in a per-call trace event so categorize can distinguish truncation from natural stop. Cost tracker + semantic pool integration parity with Hermes / Ollama. Not on `cmd/bench`'s auto-routing allowlist — substrate-agnostic, picked explicitly via `--orchestrator-substrate=lmstudio`.
- **Grader** (`pkg/grader`) — LLM-as-judge for Phase 1 quality measurement. `AnthropicGrader` scores a candidate against a fixed rubric (relevance / tone / completeness / professionalism, 1-5 each, plus notes). Defaults to Sonnet so the judge is stronger than either candidate being graded. Not part of the runtime call tree — this is the measurement layer. `AdapterGrader.Governor` (optional `*vram.Governor`) Acquires/Releases against a shared governor when set, so grader calls cooperate with the runner (and any other component) on the same VRAM budget. Required for `cmd/bench` to bound total inflight inference across the orchestrator and grader.
- **Benchmark harness** (`pkg/benchmark`) — drives established LLM benchmarks (GPQA Diamond first; MATH-500, AIME, MMLU-Pro, HLE, SWE-bench queued). `Loader → []Case`; `Orchestrator` produces an `Answer`; `Grader` produces a `Verdict`; `Runner` sequences cases through every configured Orchestrator, grades each, accumulates a Report. **Sliding window**: cases process in deterministic order so the Runner snapshots a per-window pass-rate after each case past the warmup; the resulting curve shows whether the orchestrator improves with case count (the long-term self-improvement claim — currently flat in v0 because no runtime curation is wired, scaffolding ready). Errors on individual cases are recorded in the Report, not propagated. `pkg/benchmark/orchestrator.Single` (one adapter call — frontier baseline), `Vote` (N parallel attempts + majority vote with deterministic alphabetical tie-break — orchestration arm), and `Tree` (full runner+recomposer call tree — decompose+recompose arm); all Governor-aware (every adapter call Acquires a lease). `pkg/benchmark/orchestrator.DeriveGoal` (LLM call that derives a natural-language goal from the case prompt — goal is set on `Case.Goal` by the benchmark runner before orchestrators run) and `LLMExtractor` (LLM-backed `Extractor` that uses the goal to pull the canonical answer from model output; replaces the regex extractor for non-MCQ benchmarks). `Extractor` interface is now `Extract(ctx, goal, raw) string`. `pkg/benchmark/grader.Multichoice` (extracts A/B/C/D via word-boundary regex, last-match-wins — matches "the answer is C" reasoning patterns; no LLM judge needed) and `Dual` (Primary + N Secondaries in parallel; Primary canonical, Secondary verdicts attached for sanity-check; `Agreement()` reports primary/secondary match rate). `pkg/benchmark/loader/gpqa` reads operator-downloaded JSON; correct answer placement is deterministic per case ID (SHA-256 hash) so reruns produce byte-identical prompts.
- **Vote orchestrator telemetry** — `orchestrator.Vote` accepts a `Tracer` (nil-safe → trace.Discard). Per-attempt events `vote.attempt_start` / `vote.attempt_done` / `vote.attempt_error` carry case + attempt_idx + extracted + tokens + duration_ms, and a single `vote.tally` per case carries `winning_answer`, `winning_votes`, `stakes` (v3.0), and a deterministic `distribution` string (`A=3,B=1,C=1` — sorted alphabetically). Lets operators answer "why did Vote pick X?" / "which attempts errored?" from logs without re-running.
- **Stakes-driven attempt scaling** (`pkg/benchmark/orchestrator.Vote`, v3.0) — reads `c.Stakes` per `benchmark.Case`, computes effective attempt count via `stakes.AttemptScale(level, v.N)`: Low=1, Medium=v.N, High=2×v.N. The effective stakes are stamped onto each attempt's `env.Stakes` for downstream consumers. Backwards-compatible: zero-value stakes reads as Medium so existing tests + loaders that don't set Stakes get the same behavior as pre-v3.0. The bench assigns stakes via `--stakes` (low|medium|high|rotate); rotate is the testing mode that round-robins per case so a single run produces three cost profiles. The `vote.tally` trace event surfaces effective stakes alongside attempt counts for per-case observability.
- **Curate driver** (`cmd/curate`) — thin CLI over `pkg/curation`. `--stream path.jsonl` (bench's `--stream-out` output) + `--store-dir path/` (becomes the `exemplar.FileStore` target) + `--substrate hermes|anthropic` for the cold-path session. Same `--config` / `--v` / `--otel` / `--otel-service-name` pattern as cmd/bench; properties keys under `curate.*`. Repeatable `--orchestrator-allowlist` (or `curate.allowlist.*` props) restricts which orchestrators contribute candidates. Runs a best-effort `store.GC` after the curation pass when `--max-tokens-per-action > 0`. Prints a summary (cases scanned / candidates filtered / batches processed/failed / exemplars selected vs added / adapter tokens / elapsed). Operators run this offline after a bench, or use cmd/bench's `--curate-store-dir` for the in-process post-hook.
- **Cope dispatcher** (`pkg/cope`, v3.4) — the rule-table dispatcher that reads inadequacy signals (effective confidence + stakes) and picks a coping action. `Action` is one of `Ship` / `ShipWithCaveat` / `Escalate` / `Refuse`. `RuleTable.Decide(confidence, stakes)` is the pure lookup; `Explain` returns a `Decision` with rationale. Default thresholds: HighConfidence=0.85 (ship floor), LowConfidence=0.5 (caveat floor). Escalation gated by RuleTable.EscalateAllowed (set to false when no frontier wired → falls back to Refuse rather than silently skip escalation). Zero confidence (= "no confidence reported") reads as mid-band → caveat (safe default; don't escalate on missing data). Signal-driven actions (re-run on format violation, refuse on refusal language) deferred to v3.4.x: refusal already manifests as a confidence downgrade via v3.2's adjustments, so the table routes correctly. Pure decision function — no I/O. Adapter-agnostic.
- **Coping orchestrator** (`pkg/benchmark/orchestrator.Coping`, v3.4) — `benchmark.Orchestrator` wrapper that applies the cope.RuleTable to an Inner orchestrator's Answer. On `Ship` / `ShipWithCaveat`: stamps `Answer.CopeAction` and returns inner. On `Escalate`: re-runs the case against Frontier orchestrator, pools tokens + calls into the returned Answer, stamps `escalate`. On `Escalate` when Frontier failed: tags `escalate-failed`, returns inner — bench grader still sees the inner answer (no value lost, just double-call cost paid). On `Refuse` (no frontier wired): returns empty Extracted; case fails by extraction. Emits `coping.decision` trace event per case with action + confidence + stakes + rationale. `cmd/bench` enables via `--cope` (default off; --cope-high-confidence, --cope-low-confidence tune thresholds).
- **Tree orchestrator** (`pkg/benchmark/orchestrator.Tree`) — wraps the runner+recomposer call tree as a `benchmark.Orchestrator`. The bench's per-case Answer is the result of the full Oscillitron orchestration pattern: plan → emit_subtree → child APs (process) → synthesize (recompose). Forces `PlaybookPlan` on the root so the decompose path is exercised (otherwise Evaluate would pick Process and degenerate to Single). Recomposition uses `recomposer.Synth` backed by a caller-provided Synthesizer (typically `recomposer.AdapterSynth` wrapping the same substrate). `treetrace.go` provides per-case tree-state debugging output. Distinct from Single (1 call), Vote (N parallel + majority), and Coping (Vote + escalation). Governor-aware.
- **Confidence calibration** (`pkg/benchmark/calibration`, v3.3) — buckets cases by `Answer.Confidence` band and reports pass-rate per band per orchestrator. Tests whether the calibrated confidence is a useful signal: if higher bands have higher pass rates (slopes up), confidence is informative; if flat, it's noise. `Compute(report, bands)` returns a `Summary{Rows, Empty}`. `DefaultBands` are `low (<0.50)`, `medium (0.50-0.85)`, `high (>=0.85)` — tuned to match the v3.4 coping rule-table thresholds. `FormatTable` renders a stdout-friendly table. `Empty=true` when no confidence was reported (pre-v3.3 path); `FormatTable` then prints a one-line "no confidence values reported (skip)" message instead of an empty grid. `cmd/bench`'s `printReport` renders this table after the failure categorization, automatically — no flag needed.
- **Failure categorization** (`pkg/benchmark/categorize`) — heuristic classifier that buckets each `OrchestratorResult` failure beyond pass/fail. Buckets: `pass`, `format_no_letter` (extracted=""), `wrong_letter` (committed but ≠ expected), `refusal` (matches "I (cannot|can't|won't|am unable to|...)"), `empty_response` (raw is empty/whitespace), `adapter_error` (Err set), `other` (last-resort). Order matters: adapter_error → pass → empty → refusal → format → wrong → other, because refusals often produce no letter AND a refusal sentence (refusal is the more informative bucket). `Classify` is per-result, `Aggregate` per-Report, `FormatTable` renders a stdout table. No LLM calls — fast, deterministic, free. `cmd/bench`'s `printReport` now includes the categorization table after the aggregate stats. Surfaces *why* failures fail so operators pick the right intervention (recipes for format, substrate change for wrong-letter, jailbreak for refusal, etc.).
- **Bench driver** (`cmd/bench`) — `--benchmark gpqa --cases <path>` runs the benchmark; substrate plumbing mirrors `cmd/phase1` (per-role `--orchestrator-substrate`/`--frontier-substrate` plus model/url). **Substrate auto-routing**: `--orchestrator-substrate=auto` (the default) inspects `--orchestrator-model` and routes small models (phi*, llama3.2:3b/1b, gemma:7b, gemma2:9b/2b, qwen2.5:3b/7b, qwen2.5-coder:3b/7b — see `resolveSubstrate` in `cmd/bench/main.go`) through `pkg/adapter/ollama` (direct, no Hermes envelope); larger models stay on Hermes. Operators force a specific substrate via `=hermes`, `=ollama`, or `=anthropic`. Frontier role never auto-routes to ollama — the baseline must stay a fair comparison. Constructs ONE `*vram.Governor` from `--model-layers`/`--model-kv-hidden`/`--model-kv-dtype-bytes`/`--model-context-size` (omit any → bench uses `vram.DefaultVRAMModel` under `MaxConcurrencyCeiling=8`; library-managed governor, pass all four for accurate per-model throttling). The same governor is threaded into both orchestrators and the grader so all inference shares one VRAM budget. Default config: orchestrator=local Hermes (Vote-5), frontier=Anthropic API (Single). Dataset snapshots live under `cmd/bench/cases/` (operator-downloaded, never committed — `.gitignore` enforces; see `cmd/bench/cases/README.md` for the `huggingface-cli`/GitHub → JSON recipe). Report prints per-orchestrator aggregate stats, the sliding-window evolution table, and the first 3 failures per orchestrator for spot-checking the extractor/grader. **LLM extraction**: per-benchmark regex extractors are replaced by a single `LLMExtractor` + `GoalDeriver` pipeline — `GoalDeriver` (`RunnerConfig.GoalDeriver`) runs once per case before orchestrators (derives answer-format goal from the prompt via LLM call, stores in `Case.Goal`), then `LLMExtractor` uses that goal to extract the canonical answer from each orchestrator's raw output. `benchmarkConfig` bundles Loader + Grader only; extraction is adapter-backed and benchmark-agnostic. `--report-out path.json` additionally dumps the full Report as snake_case JSON (errors stringified, secondary verdicts preserved) so downstream tools (notebooks, plotters, CI gates) can replay the analysis without rerunning the bench — see `pkg/benchmark.WriteJSON` / `WriteJSONFile`. `--stream-out path.jsonl` appends each CaseResult as one JSON line via `RunnerConfig.OnCase` (`benchmark.JSONLStreamer` with `Flusher: f.Sync` for crash safety) — `tail -f` shows live progress and a crashed multi-hour run leaves partial-but-valid JSONL on disk. **Properties config**: `--config bench.properties` fills in any unset CLI flag from a `.properties` file (CLI always wins). Keys mirror flag names with `bench.` / `trace.` prefixes — see `cmd/bench/bench.properties.example`. **OTel shipping**: `--otel` (or `trace.otel.enabled=true`) ships every trace event to OpenTelemetry via OTLP HTTP — operator points `OTEL_EXPORTER_OTLP_ENDPOINT` at a collector. Combine with `-v` (kept via `trace.Multi`) to also see events on stderr. `--otel-service-name` sets the OTLP `service.name` resource attribute. **Post-hook curation**: `--curate-store-dir DIR` (or `bench.curate.store_dir` in properties) triggers `pkg/curation.Run` after the bench completes, writing selected exemplars to `DIR`. Requires `--stream-out`. Reuses the orchestrator adapter as the cold-path session (operators who want a different cold-path substrate run `cmd/curate` separately). `--curate-action` keys the exemplar partition (default `process`); `--curate-batch-size`, `--curate-min-score` tune the curation run. **Warm-path retrieval** (closes the self-improvement loop): `--use-store DIR` wraps BOTH orchestrator adapters with `pkg/adapter/curated.Adapter` reading from the same `exemplar.FileStore`. Each call retrieves the top-K relevant exemplars and prepends them as few-shot context before the model sees the question. `--use-store-action` (default `process`) sets the `ActionOverride` so the retrieval key matches whatever the cold path wrote under; `--use-store-topk` and `--use-store-max-tokens` tune the prefix budget. Two-run cycle: run 1 with `--curate-store-dir` populates the substrate; run 2 with `--use-store` benefits from it — the aggregate-vs-aggregate delta measures whether curation actually moves quality. **Cost tracking**: `--price NAME=RATE` (repeatable) and `--frontier-price RATE` configure blended USD-per-Mtok per orchestrator. AggregateStats grows `TotalActualUSD` (own tokens × own rate), `TotalFrontierUSD` (own tokens × frontier rate — the counterfactual "what would Sonnet have cost?" column), and `SavingsRatio`. Single-number blended rate is used (not separate in/out) because `Answer.TokensUsed` is already aggregated; operators who need exact I/O accounting bypass `benchmark.Pricing` and use `pkg/cost.Pricing` directly. Defaults are zero, so omitting the flags leaves cost columns empty. **System preamble**: `--system-preamble` (default `"Be terse and dense."`) sets the universal behavioral directive prepended to every adapter call (Evaluate, Execute, RawCall). Empty string disables. **Notice (v3.1)**: `--notice` (default true) wires `pkg/notice.Inspector` into the ollama orchestrator + frontier adapter; `--notice-context-size N` sets the context window the overflow detectors compare against (falls back to `--model-context-size`, then to 0 which disables overflow checks but keeps persona-heavy). Trace events `ollama.notice_assessment` (carries top_severity, signals CSV, score, detection_count) surface signals via `-v` stderr / OTel. **Stakes routing (v3.0)**: `--stakes low|medium|high|rotate` wraps the loader to assign per-case stakes. The Vote orchestrator then runs effective N attempts per case based on `stakes.AttemptScale` (Low=1, Medium=N, High=2N). Unset (default) preserves pre-v3.0 behavior. `rotate` mode round-robins across the three levels so a single bench run produces three cost profiles for measuring differentiation.
- **Phase 1 driver** (`cmd/phase1`) — the kill-or-proceed gate from `scratch/library-plan.md` §2.5. For each case in `cases.json`: runs orchestrator (N Haiku drafts → AnthropicSynthesizer with Haiku), runs frontier baseline (1 Sonnet single-call), grades both with the same rubric, reports quality + cost ratios against the §2.5 proceed/kill thresholds. Workload is email drafting (mundane office tasks with nuance — decline, schedule, clarify, pushback). Output is text-only; tool/connector execution is deferred per the "always after task completion" lock. See `references/phase1-measurement-guide.md` for operator usage and verdict interpretation.
- **Runner verifier + judge integration** — `Config.VerifierPolicy *verifier.Policy` is optional. After each return_result child of an emit_subtree plan resolves cleanly, the runner consults the policy and, if it says yes (or the child's NeedsVerification is set), injects a critique AP into the same scope. The critique's verifier_signal flows into `RunState.VerifierSignals` via the existing category branch; the recomposer never sees it. `RunState.PolicyCritiquesEmitted` distinguishes policy-injected critiques from adapter-emitted ones. When `Config.Judge` is also wired (with an optional `Config.JudgeSampler`), the runner samples per the locked rates after each critique resolves, calls the frontier Judge for an independent verdict, compares, and calls `Policy.RecordJudgeAgreement(action, agreed)`. Judge errors are non-fatal — recorded in `RunState.JudgeErrors` but never fail the run. New counters: `JudgeSamplesTaken`, `JudgeAgreements`, `JudgeDisagreements`, `JudgeErrors`.

**Deleted (no longer relevant under the uniform-node model):**
- `pkg/oscillator` — uniform-node lock kills the brain-function-typed wrapper. One adapter handles every AP; the playbook is *picked* by evaluate, not declared.
- `pkg/registry` — no `BrainFunction → instance` mapping; one adapter does it all.
- `pkg/topology`, `pkg/router`, `pkg/router/rule`, `pkg/decomposer` — already gone under the earlier call-tree refactor.

What's deliberately NOT here yet:

- Multi-instance Hermes against *real* Hermes processes — the multi-endpoint plumbing (`MultiEndpoint` builder, demo CLI properties wiring, httptest smoke test) is in place, but a smoke test against N actually-running `hermes gateway` processes on distinct ports has not been done yet. Defer until a real reason (per-playbook drift visibility) shows up.
- Anthropic API quotas / retries / rate-limit handling — `pkg/anthropic.Messages` calls the API with a basic timeout. Retries, backoff, and 429 handling are caller-side concerns and not built in (the runner already treats Judge errors as non-fatal, which is the relevant resilience).
- Critique-on-recomposed-bubble — the runner only injects critiques after return_result *children*. A plan's recomposed bubble is not critiqued (would require a v1 compose-as-AP rework).
- Approval handling — `/v1/runs/{id}/approval`. The adapter rejects approval.request events as inhibited; auto-approval / human-in-the-loop is a later PR.
- Real grader implementations beyond substring — LLM-as-judge and rules-DSL graders are seam-reserved but not built.
- **Curation layer** — programmatic writes to the semantic pool, recipe consolidation, exemplar promotion. v0 ships read-only semantic pool with operator-curated JSON; the curation layer that gates writes is the next substrate piece. Also leaves tree-merge-with-conflict-resolution as a separate Recomposer variant for future work.
- Compose-as-a-dispatched-AP with actual scope channels — v0 owns recomposition in the runner+recomposer pair; the compose playbook category exists at the adapter level but the call-tree orchestration is deferred.
- Sibling parallelism, async sub-AP emission, hardware parallelism — deferred (see parent CLAUDE.md).
- Checkpointing for inhibitor Restart — runner still downgrades Restart to Abort with annotated reason.
- Anything compliance-shaped (audit ledger, manifest, classification routing) — Phase 4.

## Build, run, test

```
go build ./...
go test ./...
go run ./cmd/oscillitron
```

Requires Go 1.26+ (current toolchain on dev machine; bumped from 1.21 on 2026-05-18).

### Pre-commit hooks

Tracked hooks live in `scripts/git-hooks/`. Git fires hooks from
`.git/hooks/` by default; one command per clone redirects it to the
tracked dir:

```
./scripts/install-hooks.sh   # sets core.hooksPath = scripts/git-hooks/
```

Idempotent — safe to re-run. The `pre-commit` hook runs `gofmt -l`
on staged Go files and `go vet ./...` on the module. No external
tooling required beyond the Go toolchain already needed to build.

There is no CI workflow in the repo yet (`scratch/ci-workflow-todo.md`
tracks it), so the local hooks are the only enforcement. **Don't skip
the install.**

### Smoke-testing the Hermes adapter against a real local Hermes

```
# In a separate shell, with hermes-agent installed and configured
# (model provider keys in ~/.hermes/.env, etc.):
hermes gateway start
# By default api_server listens on 127.0.0.1:8642. Confirm with:
curl -s http://127.0.0.1:8642/v1/models

# Then run the demo through Hermes:
go run ./cmd/oscillitron --hermes http://127.0.0.1:8642
# Or pick the model explicitly:
go run ./cmd/oscillitron --hermes http://127.0.0.1:8642 --hermes-model openrouter:openai/gpt-4o-mini
# Strict mode — error on any non-JSON response from the substrate:
go run ./cmd/oscillitron --hermes http://127.0.0.1:8642 --strict

# Or commit settings to a file and reuse:
cp cmd/oscillitron/oscillitron.properties.example oscillitron.properties
# (uncomment and edit the hermes.url / hermes.model lines, then:)
go run ./cmd/oscillitron --config oscillitron.properties
# CLI flags still win; passing --hermes "" forces back to stub mode.
```

`--hermes` uses `hermes.SingleEndpoint` (one Hermes for every playbook — the v0 dev shape). For the multi-endpoint case (one Hermes per playbook action — the locked per-instance playbook substrate design), pass a `--config` properties file that sets `hermes.endpoints.evaluate.url` plus one entry per playbook; the demo constructs `hermes.MultiEndpoint` automatically. Programmatic callers can call `hermes.MultiEndpoint(evaluate, byPlaybook)` directly.

## Conventions

- **Stdlib only** for the skeleton. Reach for external deps only when a real need lands (Hermes client, persistence, observability backend). Each new dep should be justified in `../scratch/design-notes.md` or its own ADR.
- **Interfaces in the package they're consumed in.** `Adapter` is in `pkg/adapter` because everyone consumes it. Concrete impls live in subpackages (`pkg/adapter/stub`).
- **Tests next to code** (`foo_test.go` alongside `foo.go`). Integration tests under `internal/test/`.
- **No `main` logic in `cmd/`.** `cmd/oscillitron/main.go` wires components together and runs them; all logic lives in `pkg/`.

## When to ask vs. proceed

Proceed without asking on:

- Mechanical code that implements an already-locked design (anything in library-plan §5 type signatures).
- Stdlib-only additions to existing packages.
- Test additions.
- Refactoring within a package that doesn't change its public surface.

Ask before:

- Adding a new external dependency.
- Changing the Session Envelope schema in a way that breaks JSON compatibility (library-plan §2.4 commits to schema stability).
- Picking implementations for items listed as "Open" in `../scratch/library-plan.md` §7 or `../scratch/design-notes.md`.
- Anything that touches `../inputs/` — that's user-owned per the parent provenance rule.
