# Substrate routing: small models bypass Hermes

When `cmd/bench --orchestrator-substrate=auto` (the default), the bench picks an adapter based on the configured model. Small substrates route through `pkg/adapter/ollama` (direct chat-completions, no agentic envelope); larger substrates stay on `pkg/adapter/hermes`.

## Why

Hermes is an agentic substrate built for tool-calling. From `~/hermes-agent/website/docs/guides/local-ollama-setup.md`:

> Smaller models (3B, 7B) sometimes ignore tool-call instructions and produce plain text instead of structured function calls. Solutions:
> - **Use a bigger model** — `gemma4:31b` or `gemma2:27b` handle tool calls much better than 3B/7B models.
> - **Hermes has auto-repair** — it detects malformed tool calls and attempts to fix them automatically.

The recommended local model is `gemma4:31b` (31B). Below that, Hermes's auto-repair pipeline tries to coerce plain text into tool-call shape and frequently produces gibberish.

Empirical evidence (2026-05-22, GPQA Diamond case 002, phi4-mini:latest):

| Substrate | Input tokens | Output tokens | Output text | Done state |
|---|---|---|---|---|
| Hermes → Ollama → phi4-mini | 4097 | ~8 | `"6 is to and write an generated by"` (gibberish) | (Hermes doesn't expose finish_reason) |
| Hermes → Ollama → phi4-mini, **minimal instructions** | small | streaming | Coherent chemistry reasoning ("Trans-Cinnamaldehyde + Methylmagnesium Bromide → Product 1…") | (streamed) |
| Ollama-direct → phi4-mini | 122 | 361 | 1487 chars of coherent reasoning ending with `"Answer is A) 10."` (correct) | `stop` |

The 4097 - 122 = **3975-token delta** is Hermes's agentic prefix. Small models can't think under it.

## How the auto rule works

`resolveSubstrate(role, model)` in `cmd/bench/main.go` is a case-insensitive substring match against `smallModelSubstrings`:

```
phi              — phi4-mini, phi3, phi2 (all ≤4B)
llama3.2:3b      — Hermes docs flag as "no tool calling"
llama3.2:1b
gemma:7b
gemma2:9b
gemma2:2b
qwen2.5:3b
qwen2.5:7b
qwen2.5-coder:3b
qwen2.5-coder:7b
```

Match → `ollama`. No match → `hermes`. Frontier role (the baseline) bypasses ollama entirely so the comparison stays honest.

The heuristic is intentionally a list, not a parser: model size is not always encoded in the tag (phi4-mini has no size in the name), and false-positive misrouting (wrapping a capable model in a non-agentic shim) is more painful than false-negative (small model on Hermes — which is what we already see and want to avoid).

## Overrides

| Flag | Effect |
|---|---|
| `--orchestrator-substrate=auto` (default) | Heuristic above |
| `--orchestrator-substrate=ollama` | Force Ollama-direct regardless of model |
| `--orchestrator-substrate=hermes` | Force Hermes regardless of model |
| `--orchestrator-substrate=anthropic` | Force Anthropic (cloud) regardless of model |

Same flags exist for `--frontier-substrate` and `--frontier-*`, but the frontier role never auto-routes to ollama — it's the baseline; we want a fair comparison, not a silently-downgraded one.

## Extending the allowlist

When you start using a new small open-weight model, add its tag to `smallModelSubstrings` in `cmd/bench/main.go`. The test in `cmd/bench/substrate_test.go` is the canonical place to assert new entries route correctly.

Don't try to parse the size out of the model name — phi4-mini, hermes-3, deepseek-coder don't encode size in a uniform way. Just maintain the list.

## What this doesn't fix

- The bench's playbook *instructions* (in `pkg/adapter/{hermes,ollama}/instructions.go`) are still complex JSON-protocol prompts. Small models can sometimes fail the JSON envelope; the adapter falls back to a low-confidence return_result. If a small substrate is failing the envelope more than ~20% of the time, that's a prompt-engineering problem, not a substrate-routing problem.
- Hermes itself can still be the right answer for ~30B+ models. The auto rule doesn't push everyone to Ollama-direct; it pushes *small* models there.
- Anthropic remains the right call for hosted-frontier baselines. The rule ignores Anthropic.

## Other substrates

`vllm` and `lmstudio` are explicit-only substrates. Auto routing exists to solve one specific failure mode — small open-weight models being crushed by Hermes's tool-call envelope — and it only triggers `ollama` for matches on `smallModelSubstrings`. vLLM serves production-grade capable models on real GPU clusters and LM Studio is a local-laptop frontend for the operator's chosen model; neither is the right target for "small substrate gets crushed by Hermes" heuristic. Operators who want either pass `--orchestrator-substrate=vllm` or `--orchestrator-substrate=lmstudio` explicitly.
